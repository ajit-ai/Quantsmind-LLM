# Taksh v2.0.0 — Training Stability, Task Conditioning and Reproducible Learning

**Disposition:** `v2.0.0 ENGINEERING QUALIFIED — STABILITY IMPROVED, TASK LEARNING NOT DEMONSTRATED`

This milestone answers three research questions with real experiments on
locally generated synthetic Python: whether S2 can train without collapsing
into repetitive output, whether it can produce different operations for
different requirements, and whether a run can be reproduced exactly.

> **Separate flags:** task-conditioned coding intelligence — **NOT_DEMONSTRATED**
> · independent training reproducibility — **BITWISE_REPRODUCIBLE** (for the
> cell tested) · production coding capability — `NOT_DEMONSTRATED` ·
> real-data corpus authorization — `BLOCKED` · functional correctness —
> `BLOCKED` · real-agent integration — `NOT_PERFORMED`.

## 1. Executive summary

| Question | Answer |
| --- | --- |
| Can S2 train without collapsing? | **Yes, partially.** A conservative learning rate (3e-4) turns the baseline's fixed template into prompt-dependent output: prompt sensitivity 0.00 → 0.75, distinct bodies 0.04 → 0.50, syntax-valid 0/24 → 18/24. |
| Does it learn the *requested operation*? | **No.** Only 3/24 completions contain the requested operator, and 14/24 are still degenerate. The output varies with the prompt but is not task-correct. |
| Can a run be reproduced? | **Yes, bitwise.** Two independent 24-step runs produced byte-identical checkpoints (`sha256 17d9fb6b…`) and identical loss trajectories. |
| Which cell is best? | 3e-4 from scratch (syntax 18/24, sensitivity 0.75). Initialising from the M7 baseline and continuing at 3e-4 reproduced the *collapse* (0/24, sensitivity 0.00). |

## 4. v1.9.0 collapse findings carried forward

The v1.9.0 trained checkpoint emitted one identical 64-quote completion for
all 24 prompts (`GENERIC_TEMPLATE_COLLAPSE`), and its 8/8 syntax-valid figure
was measured on a checkpoint that a later probe had overwritten. Two
questions followed, and this milestone answers both: *is the collapse caused
by the configuration (learning rate, exposure) or by the model?* and *can a
run be reproduced at all?*

## 5. Immutable artifact design

`training/experiment_artifacts.py` replaces the open-ended experiment
directory with an exclusive, immutable run space:

* `RunArtifacts(root, run_id)` creates the run directory **once**; a second
  use of the identifier is refused (this fired for real during the
  reproducibility run).
* Checkpoints, evaluations, metrics and the hash inventory are written
  atomically through a temporary file, so an interrupted write leaves no
  plausible artifact.
* `finalize()` writes the manifest and the inventory and then makes the
  artifacts read-only; **no artifact may be added to a finalized run**
  (a diagnostic probe is refused).
* `verify()` recomputes every recorded hash and fails on a mismatch.
* An evaluation record must carry the `checkpoint_sha256` it was produced
  from; a record without one is refused.
* The experiment root is refused if it lies inside the repository.

Layout: `run-id/{manifest.json, integrity/{config,curriculum,hashes}.json,
checkpoints/, evaluations/, metrics/}`.

## 7. Curriculum and contrastive pairs

`training/contrastive_tasks.py` defines six families with two variants each:
arithmetic add/subtract, conditionals maximum/minimum, list keep-positive /
keep-negative, string upper/lower, dict lookup/count-keys, loop sum/count.
Each pair differs by exactly one meaningful requirement, so a model that
ignores the instruction answers both members identically, and a model that
only copies the name still fails.

| Partition | Size | Purpose |
|---|---:|---|
| train | 80 | both variants of four families |
| A | 40 | the same templates with unseen names and constants |
| B | 16 | composed tasks (filter then total) |
| C | 24 | two families that are never trained (`dict_ops`, `loop_agg`) |
| D | 48 | matched contrastive pairs of the trained families (24 pairs × 2 variants), unseen names and constants |

## 8. Data contamination controls

The contrastive curriculum reports **CLEAN**: no identical target crosses a
partition boundary, and no withheld family appears in training. Template
sharing between train, A and D is deliberate — D asks for the *same*
operations with unseen names, which is what makes it a test of instruction
following rather than of template recall. The v1.9.0 curriculum's stricter
rule (parameter-erased duplicates are violations) is unchanged for that suite.

## 10. Learning-rate comparison and stability

| Cell | Init | LR | Loss | Val loss | Steps | Tokens | Seconds |
|---|---|---|---|---|---|---|---|
| A | scratch | 3e-4 | 8.664 → 5.544 | 5.683 | 24 | 2,084 | 11.9 |
| B | scratch | 1e-4 | 8.664 → 6.754 | 7.141 | 24 | 2,084 | 13.9 |
| C | M7 | 3e-4 | 4.647 → 2.573 | 2.665 | 24 | 2,084 | 13.2 |

Per-step instrumentation (gradient norm before clipping, parameter-update
magnitude, update-to-parameter ratio, finiteness) is recorded in every run's
`metrics/training.json`. No non-finite loss or gradient occurred in any cell.

Interpretation: the **higher** learning rate (3e-4) produced the stronger
change, and the lower one (1e-4) was more conservative but no better. A
smaller learning rate is not automatically better, and the historical 3e-3
reference was not re-run because the v1.9.0 result is already recorded.

**Task conditioning: `SURFACE_CONDITIONED_LEARNING`.** The output now depends
on the prompt (sensitivity 0.75) and the matched contrastive pairs are
differentiated 3/3, but only 3/24 completions contain the requested
operator and none matches the target exactly. The model responds to the
prompt without performing the requested computation. Static operator
agreement is not functional correctness, and no generated program was
executed.

**Initialisation finding.** Continuing from the M7 baseline (cell C) did not
help and preserved the collapse (sensitivity 0.00): the M7 distribution is
already degenerate, so short continued training reinforces it.

## 18. Recommended next research milestone

1. Scale the contrastive curriculum (hundreds of matched pairs, several
   parameter regimes) and train for thousands of steps with a pre-registered
   budget, keeping the frozen evaluation and the contrastive metric.
2. Attack the degeneracy directly: repetition-penalised sampling, an
   unlikelihood or repetition-aware objective, and a curriculum whose
   targets cannot be produced by a fixed template.
3. Keep the immutable artifact system as the only place checkpoints are
   written, so a probe can never overwrite a run again.
4. Only after operation agreement rises on held-out pairs should the
   production corpus decision (D1–D5) and the geometry decision (D6) be
   revisited.

## 19. Final-verification appendix

**Complete checkpoint digest.** The two independent runs
`runA-lr3e4-s24` and `runA3-lr3e4-s24` (separate immutable directories,
separate finalizations) produced byte-identical checkpoints with the complete
SHA-256

`17d9fb6b012e10d5aadfa0ab07c89579e2f2ab7bddb6f38c4e7e761d1050277a`

verified directly from the checkpoint files, not from a manifest field. Both
runs record 24 optimizer steps, 48 microsteps, 2,084 supervised target tokens,
seed 20261021, learning rate 3e-4, curriculum digest `e43987aec26dfaa8`,
baseline checkpoint `6f05cd3df272a775…`, identical loss trajectories, and an
evaluation record whose `checkpoint_sha256` equals the digest of the file it
was produced from. Classification: **`BITWISE_REPRODUCIBLE`**.

**Evaluation coverage.** The 24 evaluated cases are 6 from each partition
(A 6, B 6, C 6, D 6) and cover 7 families (arithmetic, conditionals,
list_ops, string_ops, composed, dict_ops, loop_agg). The 24 cases are a
**subset** of the 128 held-out examples available (A 40, B 16, C 24, D 48);
no result here may be read as performance over all of them. Operation
agreement was recomputed from the stored completions and the frozen prompts:
**3/24**, matching the report.

**Contrastive denominator.** The 3/3 differentiation figure rests on **3
matched pairs (6 cases)** in partition D, each pair differing by one required
operation. It is a small denominator and is reported as such.

**Comparison limitations.** Cell A versus Cell B is the learning-rate
comparison: identical scratch initialisation, curriculum, seed, evaluation and
step count, differing only in learning rate (3e-4 vs 1e-4); the higher rate
produced the stronger change. Cell A versus Cell C is **not** a
learning-rate comparison — it also changes the initialisation history — so it
is an initialisation effect, and Cell C versus the M7 baseline shows that
short continued training on the synthetic curriculum did **not** move the
collapsed M7 behaviour (sensitivity 0.00, syntax 0/24).

**`SCRATCH_PRETRAIN_BASELINE_NOT_AVAILABLE`.** No frozen *untrained*
scratch-initialised model was evaluated, so the syntax-validity gain of cell A
cannot be attributed to training alone; part of it may be the difference
between a random-init model and the M7 checkpoint's priors. This baseline was
not created, because that would require another run.

**Task-conditioning classification (confirmed).** The scratch cells are
`SURFACE_CONDITIONED_LEARNING`: prompt sensitivity 0.75 (A) and 0.67 (B),
distinct bodies 0.50/0.46, contrastive pairs differentiated 3/3 — but
operation agreement 3/24 and exact-target 0/24 in every cell, so
**requested-operation learning remains `NOT_DEMONSTRATED`** and no
computational correctness is claimed.

**Remaining scientific limitations.** No generated program was executed (no
verified isolation), so every statement is static. The cells are 24 steps
over 2,084 tokens on 80 training examples, far below any learning budget. The
curriculum has six families and twelve operations, so the measured
sensitivity may not transfer to real Python. The M7 baseline is itself a
collapsed model, which makes the scratch comparison the only informative one.
