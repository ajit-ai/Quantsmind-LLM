# Taksh v1.4.0 — IQ-1: QuantsMind-Agent Integration Qualification

**Disposition:** `IQ-1 PASS — REAL QUANTSMIND-AGENT INTEROPERABILITY VERIFIED — MODEL CAPABILITY INSUFFICIENT`

This report records a real, local, end-to-end integration between the Taksh
serving application and the **actual QuantsMind-Agent provider code**, using
an isolated configuration only. No source file in either repository was
modified for this qualification, and neither repository was committed,
pushed, tagged or released.

> **What this does and does not prove.** The real QuantsMind-Agent provider
> (its own `OpenAICompatProvider`, its own configuration loader, its own error
> types) reached the running Taksh server over localhost HTTP and completed
> requests, including model discovery, a basic chat, a Python completion, an
> instruction, three error paths and a shutdown/recovery cycle. That proves
> interoperability of the *transport and contract*. It does **not** prove
> Python coding ability: every sample Taksh produced was invalid Python, and
> functional correctness could not be measured because secure execution is
> unavailable on this host.

## 3. Integration architecture

```text
QuantsMind-Agent                        Taksh
----------------                        -----
ConfigManager(default_paths())
  -> ProviderSettings(name="openai_compatible",
                      base_url="http://127.0.0.1:<port>/v1",
                      model="qm-code-m3-9m",
                      capability_overrides={tools:false, streaming:false,
                                            structured_output:false})
  -> build_provider(settings)            serving/openai_server.py
     = OpenAICompatProvider  --httpx-->    GET  /v1/models
        (GET  {base_url}/models)          POST /v1/chat/completions
        (POST {base_url}/chat/completions) GET /health
```

The agent's provider already speaks the OpenAI contract over `httpx`, already
treats `127.0.0.1` as a local endpoint that needs no credential
(`ProviderSettings.requires_api_key()` returns `False` for local hosts), and
already accepts per-endpoint capability declarations through
`capability_overrides`. **No source change was required: the integration is
configuration-only (ROUTE A).**

## 4. Configuration-only decision

The configuration was written to an isolated directory selected with the
agent's own `QM_CONFIG_DIR` environment variable, so the real application
configuration was never touched (and did not exist at
`%LOCALAPPDATA%\QuantsMind-Agent\QuantsMind-Agent\config.toml`):

```toml
schema_version = 1

[provider]
name = "openai_compatible"
base_url = "http://127.0.0.1:56035/v1"
model = "qm-code-m3-9m"
timeout_seconds = 60.0
max_output_tokens = 256
temperature = 0.0

[provider.capability_overrides]
tools = false
streaming = false
structured_output = false
```

No credential was created, transmitted or stored. The default provider was
not replaced: the isolated configuration is used only by the qualification
process.

## 10. Security and operational limitations

* The server was bound to `127.0.0.1` only; no public exposure, no remote
  request, no cloud service, no paid API.
* No credential was created or used: the agent treats a local endpoint as
  unauthenticated, and the Taksh server was started without a key.
* The isolated configuration directory lives outside both repositories; logs,
  probes and the captured samples live under a temporary directory.
* Generated code was never executed: the evaluator's sandbox is blocked by
  design on this host.
* The Taksh endpoint rejects tool calling, structured output and streaming
  explicitly, so no agent workflow may silently depend on them.
* The agent's capability declaration is advisory: a caller that supplies tools
  still sends them, and the server refuses. An agent configuration that
  relies on tools will fail loudly, which is the intended behaviour.
* **Production readiness is not established.** The endpoint is a local,
  experimental provider for a 9.36M-parameter base model whose output was
  invalid Python in every sample; nothing here supports a production
  deployment claim.
* **No training and no new benchmark qualification occurred.** This exercise
  started and served existing checkpoints only, and it re-used the v1.4.0
  capability suite rather than introducing a benchmark.

## 11. Required follow-up work

1. **Corpus and licensing (D1–D5, D3).** No authorised corpus exists, so no
   model can be trained for this integration to be useful.
2. **Capability.** The current checkpoint cannot produce valid Python through
   the agent; the remedy is data and training, not integration work.
3. **Agent-side provider selection.** The route is configuration-only, but an
   operator must still choose the experimental provider in the UI/settings;
   this qualification deliberately did not change the default provider.
4. **Model-id validation.** The server should reject unknown model ids
   (design change, proposed for a later version).
5. **Streaming/tool workflows.** If QuantsMind-Agent's coding workflow
   requires them, that workflow is blocked against Taksh today and the
   profile says so.
