## 3. v2.0.0 learning limitations carried forward

v2.0.0 trained on **bare reference code** while evaluating with an
instruction plus a signature. A causal model can only condition on tokens it
has seen, so that setup could never teach instruction-to-operation mapping at
any learning rate — and the measured result (operation agreement 3/24, exact
target 0/24) is exactly what it predicts.

## 4. Supervision alignment audit

`training/supervised.py` makes the supervision explicit: prompt = instruction
+ signature (24 tokens in the worked example), target = body (7 tokens) plus
the end-of-document token, loss = response only.

```
instruction : "Write a function that returns the sum of two integers."
signature   : "def add_values(left, right):"
target      : "    return left + right"
tokens      : 31 (24 prompt + 7 target)
supervised  : 7 positions (6 body + terminator at index 30)
masked      : 23 positions
verification: no defects
```

**Defect found and corrected.** The first implementation masked
`labels[0:prompt_len]`, which also masked the label predicting the *first
target token* (`labels[prompt_len - 1]` predicts `ids[prompt_len]`). The model
never learned to emit the first body token, so at inference it produced the
terminator immediately and every completion was empty (0 tokens, 24/24
`eos_terminated`, training loss 2.42). The fix masks exactly `prompt_len - 1`
labels, and `verify_supervision` now asserts that count so the off-by-one
cannot recur silently. Failure tests cover empty instruction/target, missing
terminator, truncation that removes the required operation, mask misalignment
and label-count mismatch.

**Audit verification of the corrected mask (independent, read-only).** Every
one of the **98 examples** in all six partitions was re-supervised and
re-verified: the label that predicts the first target token is supervised in
98/98, the end-of-document label is supervised in 98/98, the last label is the
terminator in 98/98, no example was truncated, and `verify_supervision`
reported **0 defects**. The masked label count equals `prompt_len - 1`
exactly (for example `T-add-000`: 31 tokens = 24 prompt + 6 body + 1
terminator, 7 supervised positions `23..29`, 23 masked positions `0..22`).
The worked example above is therefore accurate, and the earlier v2.0.0-era
defect is confirmed fixed rather than merely asserted.

### 9.3 Diagnosis and correction of the evaluator defect

The stored `syntax_valid 0/24` and `exact_target 0/24` were **evaluator
artifacts, not model behaviour**. The original `evaluate_supervised` built the
program as `example.prompt_text + continuation`, and `prompt_text` begins with
the natural-language instruction. `ast.parse` therefore failed on every program
— including the *reference* program, whose dump was `None` in **24/24** cases,
so `exact_target` was false by construction.

**Fixed in this remediation.** `training/supervised_train.py` now reconstructs
source from `signature + continuation` only (the identical rule is applied to
the reference body and to the generated continuation), handles indentation
explicitly, and classifies the operation structurally from the returned
expression or computation (`add`, `subtract`, `multiply`, `max_gt`, `min_lt`,
`mapping_get`, `mapping_len`, `upper`, `lower`, `keep_positive`,
`keep_negative`, `count_items`, `sum_items`) instead of from marker
substrings. The operator-token metric is retained unchanged for historical
comparison and is never used for the structural verdict. Re-running the stored
checkpoint through the corrected evaluator regenerated all 24 completions
**byte-identically** (checkpoint `02cc86eb…` unchanged before and after) and
produced the table in 9.2; the tiny set is 6/6 parse, 6/6 structural and 6/6
exact. Ten focused regression tests pin the reconstruction, the refusal to
credit an unparsable or unrelated expression, and the distinction between
`complete_and_exact` and `complete_correct_operation`.

Two further facts are established from the stored artifacts:

* the completions are **complete**, not truncated: every one of the 24
  generations ended with `finish_reason = "stop"` (EOS) after 6–22 tokens,
  well inside the 64-token generation budget; the baseline model, by contrast,
  hit the budget 24/24 times (`finish_reason = "length"`, 64 tokens);
* the reference bodies the model was trained on are short by construction
  (the curriculum bodies are one to four lines), so a 6–22 token completion
  that matches the reference AST *is* a complete function.

**Reading (corrected).** The model learned to *produce the requested
implementation*: complete, correct bodies for trained instructions (4/4),
unseen function names (4/4) and matched contrastive pairs (4/4), and it
stopped repeating (degenerate 0/24 against the scratch baseline's 24/24).
It did **not** learn to paraphrase: on unseen instruction wordings it
reproduced the trained body only 1/4, and it neither composes (0/4) nor
transfers to the withheld family (0/4) — for both it produced a plausible but
wrong body, which is a *wrong answer*, not a refusal.

## 16. Scientific limitations

* Every measurement is static: no generated program was executed, because no
  verified isolation mechanism exists on this host. Structural results are AST
  comparisons only.
* The evaluation uses 4 cases per partition (24 in total) — a smoke set. The
  partition populations are 22/22/22/12/8/12, so a rate over 4 cases is
  reported with its denominator and no partition rate is generalised.
* Within a partition the same operation repeats with identical text, so the
  evaluated cases are not independent samples of distinct operations. The
  audit confirmed that identical completions are credited across several
  prompts (`    return left + right` is credited for `T-add-000`, `V-add-000`
  and `C-00-add`; `    if left < right:\n        return left\n    return right`
  is produced for `C-01-minimum` **and** for both `H3-lookup` cases, where it
  is correctly *not* credited), so the operator-token metric must be read
  together with the structural metric.
* The operator-token metric is looser than the structural metric: it matches a
  marker anywhere in the prompt-plus-continuation text, so it credited two
  completions that do not parse. The audit preserves the original metric for
  comparison and adds the structural one; an incomplete output is never
  counted as correct.
* The completions are short (6–22 tokens) because the curriculum bodies are
  short (one to four lines). Length is therefore not evidence of truncation:
  every trained generation ended with EOS well inside the 64-token budget.
* The training set is 22 examples and the run is 240 steps over 6,421
  supervised tokens: two orders of magnitude below any realistic budget.
* The model was trained from scratch, so it has no pretraining prior; the
  frozen scratch baseline (0/24 operation agreement, 24/24 degenerate) is the
  correct comparator, and the M7 checkpoint is not one.
* The corrected metrics were first computed read-only, outside the repository,
  against the stored completions, and are now produced by the milestone's own
  evaluator. Re-running the stored checkpoint regenerated all 24 completions
  byte-identically and reproduced the same counts; the read-only recomputation
  is retained as an independent cross-check.

   `evaluate_supervised` now parses `signature + continuation` (never
   `prompt_text + continuation`) and reports a structural operation class in

   milestone's own output.
2. **Add a regression test for the metric — DONE.** Ten tests in
   `tests/test_v210_supervision_learning.py` pin the parse of known-good

   prematurely terminated and unrelated-operator bodies.
3. **Attack instruction generalisation, not memorisation.** The model
   reproduces trained bodies exactly but reproduces only 1/4 unseen
