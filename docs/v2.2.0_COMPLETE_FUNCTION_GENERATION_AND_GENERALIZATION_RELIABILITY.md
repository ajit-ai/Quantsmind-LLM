Status: complete experiment, changes unstaged and uncommitted

## 1. Executive summary

v2.2.0 asked whether the existing 9.36M-parameter S2 model can generate complete
Python functions across unseen instruction paraphrases, unseen parameter names,
and simple compositions, without changing tokenizer, geometry, or historical
checkpoints.

The experiment used a 162-case frozen suite (E1–E6), a frozen v2.1.0 checkpoint,
and four controlled cells: A (v2.1.0 T), B (11 trained operations × 6 variants),
C (B + 4 compositions × 5 variants), and a repeat of C. All cells trained for
150 steps from the same checkpoint with equal update counts.

The aggregate exact-match rate rose from 24/162 (14.8%) at baseline to 33/162
(20.4%) in cell C. That gain came almost entirely from paraphrase variants that
retained the original signature (E2: 11/33 → 20/33). Functions with new
parameter names did not become runnable: E1 exact stayed at 1/33 and binding was
2/33. No cell produced a single complete composition (E4 0/24), no mapping
function was generated (E5 0/24), and the 150-step cell C collapsed on
composition prompts into repeated operator tokens. A supplementary 1500-step
retrain produced 3/24 compositions, all from compositions seen in training;
unseen compositions remained 0/12.

The engineering work is qualified: the suite was frozen before training, all
artifact inventories verify, the repeat run is identical, and the full test
suite passes (1328 passed, 1 skipped). The capability claim is not: the model
learned more of the training distribution, not a general function-generation
mechanism.

## 2. Scope and non-goals

In scope:

- a static, composition-aware analyzer that never executes generated code;
- a frozen 162-case evaluation suite covering paraphrases, parameter names,
  contrastive operations, compositions, held-out mapping operations, and
  negative controls;
- controlled continued training from the frozen v2.1.0 checkpoint;
- paired comparison against the same checkpoint on the same suite;
- reproducibility, artifact integrity, and regression evidence;
- an honest generalization verdict.

Out of scope, and unchanged: tokenizer, vocabulary (5,822), context length (512),
model geometry, historical checkpoints, serving contract, real-world code,
downloaded datasets, code execution, deployment, and v2.3.0.

## 5. Implementation

New modules, all importable without side effects and without executing generated
programs:

- `training/program_analysis.py` — AST analyzer. It normalizes parameters by
  position (`p0`, `p1`, …), collapses local names, canonicalizes commutative
  `Add`/`Mult` for composition keys, preserves operand order for exact keys, and
  records operations, binding, and control-flow shape. It returns `parses`,
  `body_dump`, `program_signature`, `shape`, `operations`, `params_used`,
  `undefined_names`, and a structural `key`.
- `training/generalization_tasks.py` — E1–E6 suite and cells A/B/C. It asserts
  sizes at construction time and exposes a canonical digest.
- `training/generalization_eval.py` — prompt construction, generation, static
  scoring, partition summaries, negative-control guard, and paired deltas.
- `training/continued_training.py` — continued training from an existing
  checkpoint with the v2.1.0 schedule, loss masking, gradient accumulation, and
  artifact checkpoint serialization.
- `scripts/run_v220.py` — immutable run orchestration (`freeze`, `baseline`,
  `train`, `all`).
- `scripts/aggregate_v220.py` — paired analysis and negative-control guard.
- `tests/test_v220_generalization.py` — 24 tests covering analyzer behavior,
  suite sizes, cell composition, scoring, negatives, and JSON serialization.

No tracked file was modified. The serving module, tokenizer, model geometry, and
historical v2.1.0 artifacts were left untouched.

## 8. Static metrics

- `parses`: the reconstructed function parses as Python.
- `exact`: normalized AST body is identical to the reference.
- `structural`: every expected operation appears in the generated program.
- `binding`: normalized used parameters match the reference and no undefined
  names remain.
- `control_flow`: normalized statement shape matches.
- `composition_match`: canonical structural key matches, distinguishing
  `(a + b) * c` from `a + b * c`.
- `template_hit`: generated program parses and contains at least one known
  operation. This is a negative-control diagnostic, not a success metric.
- Negative controls are forced to `exact = structural = composition_match =
  false` before aggregation; an abstention is safe but is not credited.

## 12. Held-out paraphrases

E2 changed only instruction wording, keeping the training signature. Cell C
reached 20/33 exact (60.6%, Wilson 95% CI 43.7–75.3) versus 11/33 (33.3%) at
baseline. Per instruction variant, cell C produced 5/11, 8/11, and 7/11 exact.

This is the one positive transfer signal in v2.2.0: the model can follow some
unseen wordings when the function signature remains familiar.

E3 confirms the boundary. It contributed 12/24 exact in every run, but all 12
were the unmodified base variant; the renamed-plus-paraphrased variant was 0/12
in every run. Paraphrase alone transfers partially; paraphrase plus signature
change does not.

## 13. Parameter-name binding

E1 exact was 1/33 (3.0%, Wilson 0.5–15.3) in cell C, while structural operation
preservation was 28/33 (84.8%) and binding was 2/33.

The single exact E1 success was `count_values` with the parameter still named
`values`, i.e. a training signature. In the other name variants the model
emitted the training parameter names (`left`, `right`, `values`) or invented
names, so the program parsed and performed the right operation but was not
runnable under the requested signature.

Conclusion: operation recognition improved; parameter-name generalization did
not. Structural scores overstate usability here and are reported separately for
that reason.

## 14. Composition transfer

E4 was 0/24 exact and 0/24 composition-match in baseline, A, B, and C. Cell C
parsed only 9/24 composition cases, and its outputs collapsed into repeated
operator tokens such as `return ( * * * …` and `return - - - …`.

A supplementary 1500-step retrain on cell C (not pre-registered) produced:

| E4 subset | Exact | Structural | Parses |
|---|---:|---:|---:|
| Seen compositions (12) | 3 | 8 | 8 |
| Unseen compositions (12) | 0 | 2 | 8 |
| All (24) | 3 (12.5%) | 10 | 16 |

The three exact cases were `subtract_then_multiply` and two
`filter_positive_count` variants, all seen in training. No unseen composition
became exact. A 600-step exploratory retrain reached 0 exact and 10 structural
on E4. Longer training therefore buys partial memorization of seen compositions,
not composition generalization, and it degrades E1 (structural 28 → 19 at 1500
steps).

## 15. Held-out mapping operations

E5 was 0/24 exact and 0/24 structural in every primary cell. Parsing rose from
5/24 to 14/24, but the generated programs did not implement lookup, key counts,
default lookup, or membership. Mapping remains a held-out family with no
demonstrated transfer.

## 16. Negative controls and degeneration

All runs kept 24/24 negative cases uncredited; no malformed, undefined-name,
side-effecting, empty, or unsupported-call output received exact or structural
credit. Template-hit diagnostics were: baseline 23/24, A 23/24, B 16/24, C 1/24,
supplementary 1500-step 8/24.

The cell C drop is not a safety improvement. It reflects generation collapse:
negative prompts often produced repeated tokens rather than plausible programs.
The E6 guard prevents false credit, but it cannot turn degeneration into a
capability claim.

## 17. Cell C degeneration and the limitation of token loss

Cell C's final training loss was 0.283 (validation 0.194), all losses finite,
and gradient norms stayed finite. Nevertheless, composition prompts generated
repeated operators and the E4 parse rate fell to 9/24. The repeat run was
case-for-case identical, so this is deterministic behavior of this training
configuration, not sampling noise.

The lesson is methodological: token-level training loss is not a sufficient
early-stop signal for this model. A generation-side canary (a few fixed
composition prompts) should gate future continued-training runs. That canary was
not part of the pre-registered v2.2.0 protocol; it is a recommendation, not a
retroactive change.

## 20. Claim assessment

- **Complete-function generation**: partial. More complete functions were
  produced in aggregate, but the gain is wording-driven, and composition and
  changed-signature cases remain unwritable.
- **Generalization**: not demonstrated. The only positive signal is instruction
  paraphrase with a familiar signature. Parameter renaming, unseen
  compositions, and held-out mapping operations all fail.
- **Reliability**: engineering reliability is strong (frozen suite, verifiable
  artifacts, deterministic repeat, full regression). Model reliability is weak:
  cell C collapsed on an entire partition while token loss stayed low.
- **Safety**: negative controls were never credited, but no generated code was
  executed, so this is a static guard, not a runtime safety result.

## 21. Disposition

**v2.2.0 COMPLETE-FUNCTION LEARNING IMPROVED, GENERALIZATION NOT DEMONSTRATED**

This disposition is deliberately narrower than “qualified”. The experiment
improved the aggregate exact count and produced a reproducible paraphrase
signal. It did not produce a runnable function for a new parameter name, a
single complete unseen composition, or a held-out mapping operation. Cell C also
demonstrated a generation-collapse failure mode that the training loss did not
reveal. Deployment or promotion is not authorized by this result.

## 22. Limitations and threats to validity

- Primary cells used one seed; only cell C was repeated. Training-variance
  intervals are not available.
- The 150-step budget and 1e-4 learning rate were pre-registered but not swept.
  The 600- and 1500-step supplements show strong sensitivity to this choice.
- The suite has 162 cases; partition-level confidence intervals are wide
  (e.g. 0/24 has a 95% upper bound of 13.8%).
- E1 and E2 isolate name versus wording only partially; E3's second variant
  changes both at once.
- The analyzer canonicalizes commutative addition and multiplication for the
  composition key. It is a structural check, not a semantic equivalence proof.
- Negative controls are static and small; no generated program was executed, so
  runtime correctness, security, and resource behavior are unmeasured.
- The validation partition shares signatures with training and was used only for
  loss, not for capability selection.
- Only one 9.36M-parameter checkpoint was studied. No scaling claim is possible.
- RAM pressure (0.38 GiB free at start) forced sequential runs and limited
  parallelism; no run was lost, but larger sweeps were not attempted.
