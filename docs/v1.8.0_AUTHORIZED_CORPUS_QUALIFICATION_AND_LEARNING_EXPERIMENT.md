# Taksh v1.8.0 — Authorized Python Corpus Qualification and Learning Experiment Preparation

**Disposition:** `v1.8.0 ENGINEERING QUALIFIED — CORPUS AND LEARNING PROTOCOL READY FOR OWNER DECISIONS`

This version qualifies the existing Python corpus candidates with verifiable
evidence, prepares owner-facing authorization material, diagnoses the cause of
repetitive generation, and specifies a measurable learning protocol. It does
**not** approve a source and does **not** run real-data training.

> **Separate flags:** coding improvement — `INSUFFICIENT_EVIDENCE` ·
> production corpus authorization — `BLOCKED` · experiment execution —
> `NOT_AUTHORIZED_FOR_EXECUTION` · functional correctness — `BLOCKED`.

## 6. Repetition root-cause analysis

Ten hypotheses were classified against the evidence. The decisive experiment
was a controlled decoding comparison (same checkpoint, tokenizer, prompt set,
seed and 64-token budget; only the decoding strategy varied).

| Strategy | Syntax-valid | Complete program | Degenerate | Unique-token ratio | Mean latency |
| --- | ---: | ---: | ---: | ---: | ---: |
| greedy | 1/8 | 1/8 | **8/8** | 0.197 | 2.49 s |
| temperature 0.8 (seed 1234) | 0/8 | 0/8 | 0/8 | 0.707 | 1.85 s |
| top-k 50 (seed 1234) | 0/8 | 0/8 | 0/8 | 0.674 | 2.56 s |
| top-p 0.95 (seed 1234) | 0/8 | 0/8 | 0/8 | 0.779 | 1.43 s |

Repetition penalty is **not supported** by the shared sampler and is
documented as unavailable rather than emulated.

| Hypothesis | Verdict | Evidence |
| --- | --- | --- |
| greedy decoding collapse | **SUPPORTED** | greedy is 8/8 degenerate at a 0.20 unique-token ratio; sampling removes degeneracy entirely (0/8) — but produces 0/8 valid Python, so diversity is not improvement |
| insufficient training-data diversity | PARTIALLY_SUPPORTED | the historical corpus covers 6–9 repositories; the candidate metadata shows narrow coverage |
| synthetic-family overfitting | PARTIALLY_SUPPORTED | 30.3% next-token accuracy on the synthetic validation split, 0/16 on held-out families |
| tokenizer fragmentation | PARTIALLY_SUPPORTED | 42.9% of keywords and 33.3% of common identifiers fragment; it inflates prompts but cannot alone produce the collapse |
| model capacity | UNTESTED | no larger model has been trained under the same protocol |
| EOS / termination behaviour | NOT_SUPPORTED | every completion ended on the budget, and the EOS id resolves correctly |
| repetition in the training examples | UNTESTED | requires source-content review that is not authorized |
| objective / checkpoint quality | PARTIALLY_SUPPORTED | the objective and masks are test-verified; the historical run's own metrics were not recorded in a re-checkable form |
| prompt distribution mismatch | PARTIALLY_SUPPORTED | the corrected measurement uses code prefixes and the model still repeats |
| evaluation task difficulty | NOT_SUPPORTED | greedy 1/8 versus sampled 0/8 shows the cases are not the discriminating factor |

**Root-cause confidence: partial.** The evidence supports "the model's
distribution is degenerate on this corpus, and greedy decoding exposes it",
but it does not separate data breadth from capacity. The highest-value next
diagnostic is an authorized, small training run on an approved corpus,
measured with the same protocol.

**Confirmed defect fixed.** The nucleus (`top_p`) path in
`serving/local_inference._filter_logits` scattered along the batch dimension
instead of the vocabulary dimension, so any request with `top_p < 1` raised
"index out of bounds". The fix is two lines and is covered by a regression
test.

## 7. Tokenizer findings

Measured on 120 local Python files (1,041,666 characters, 350,223 tokens):
2.9743 characters per token; 20 of 35 keywords in a single token (42.9%
fragmented); 12 of 18 common identifiers in a single token (33.3%
fragmented); indentation is cheap (four spaces = 1 token, newline = 1 token);
most punctuation is 1 token (`->` and `==` are 2); long identifiers cost
9–17 tokens; the unknown-token id is 3 and is essentially never produced.
The tokenizer was measured, never modified.

## 8. Data diversity findings

Metadata-only: `code_corpus_v2` covers 9 repositories with no dominant
licence above 72% and no duplicate content; the M3 split covers 6
repositories with a similarly flat mix; `instruct_v1` and `code_sft_v0` carry
no repository identity, so their diversity cannot even be assessed. The
v1.5.0 synthetic diagnostic is narrow by construction (six template families,
four of them in training) and showed memorisation without transfer.

## 9. Learning experiment protocol

`training/learning_protocol.py` freezes the protocol: eleven evaluation
dimensions (next-token accuracy, validation loss, syntax-valid rate,
complete-program rate, degenerate-repetition rate, held-out family rate,
novel identifier handling, unseen composition generalisation, memorisation
indicators, context-limit failures, EOS behaviour), nine experimental
controls (same checkpoint family, tokenizer, frozen cases, generation
configuration and evaluation implementation; explicit train/validation/test
separation; fixed seeds; recorded artifact hashes; independent held-out task
families), five success criteria and nine stop conditions. A lower training
loss is explicitly **not** among the success criteria. The protocol states
that the eight-case Track A suite is a smoke test and cannot support a
capability claim, and the real-data experiment remains
`NOT_AUTHORIZED_FOR_EXECUTION` behind seven gates (rights, provenance,
contamination, frozen corpus revision, accepted compute feasibility, frozen
evaluation protocol, explicit owner authorization of the specific run).

## 10. Compute feasibility

Measured: 8 logical cores, 3.91 GiB RAM, 189.8 GiB free disk, Python
3.14.7, torch 2.13.0+cpu, 4 torch threads, no accelerator; the processor is
reported as a hash. S2 training memory is 0.109 GiB (0.035 weights + 0.070
optimizer + 0.004 activations) at batch 1 and context 512, and measured
inference is roughly 35–40 tokens per second per case. A bounded diagnostic
run of a few million tokens is realistic; a 100M-token run is on the order of
a week locally. **Recommendation: `S2_DIAGNOSTIC_CONTINUE`** — the S2 rung
and this host can support a short, controlled experiment, while a larger
coding model would need new compute that is neither provisioned nor
authorized here.
