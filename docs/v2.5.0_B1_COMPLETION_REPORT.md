## 1. Files changed and reasons

Changed source / evaluation files (B1 increment):

- `evaluation/csharp/diagnostics.py` — fixed diagnostic category bucketing. Demonstrated defect:
  Roslyn parse error `CS1002` was bucketed as `semantic` and type-conversion error `CS0029` was
  bucketed as `syntax` because classification used zero-padded string prefixes instead of numeric
  error-code ranges. Replaced with numeric-range classification (`1000 <= number < 2000` → syntax;
  other positive compiler error numbers → semantic; `CS8…` → nullable; async codes → async).
- `evaluation/csharp/runner.py`, `evaluation/csharp/suite.py`, `evaluation/csharp/__init__.py` —
  bounded local toolchain support for C# probes (compile-only by default, explicit opt-in execution,
  temp dir cleanup, timeout enforcement).
- `evaluation/csharp_async/` — async/await probe re-export module.
- `evaluation/safe_execute.py` — restricted AST gate and isolated execution for approved pure
  fixtures (execution disabled by default).
- `data/contracts/csharp_v1.yaml` — proposed C# data/safety contract (untracked new file).
- `serving/languages.py` — shared language normalization for C# prompts.
- `serving/local_inference.py` — binding repair applied by default via `generate_ids(..., binding_repair=...)`.
- `training/binding_repair.py` — deterministic conservative completion repair.
- `training/exec_filter.py` — opt-in execution-backed candidate filter.

Changed / added tests and docs:

- `tests/test_csharp_evaluation.py` — focused C# evaluation tests; added regression test
  `test_compiler_error_categories_use_numeric_code_ranges` (CS1002→syntax, CS0029→semantic, CS8602→nullable,
  CS1998/CS4014→async).
- `tests/test_binding_repair.py`, `tests/test_binding_repair_conservative.py`,
  `tests/test_binding_repair_c2_qualification.py`, `tests/test_binding_repair_qualification.py` —
  binding repair unit / qualification / conservative / C2 tests.
- `tests/test_v200_training_stability.py`, `tests/test_v210_supervision_learning.py` — fixed
  protected-artifact guard to use `git status --porcelain --untracked-files=no` (untracked new files
  are new work, not modifications of protected artifacts).
- Docs: `docs/v2.5.0_CSHARP_EVALUATION_STATUS.md`, `docs/v2.5.0_PYTHON_BINDING_REPAIR.md`,
  `docs/v2.5.0_BINDING_REPAIR_QUALIFICATION.md`, `docs/v2.2.0_COMPLETE_FUNCTION_GENERATION_AND_GENERALIZATION_RELIABILITY.md`.
