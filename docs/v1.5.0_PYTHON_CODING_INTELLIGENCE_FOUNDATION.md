# Taksh v1.5.0 — Python Coding Intelligence Foundation

**Disposition:** `v1.5.0 ENGINEERING QUALIFIED — CODING CAPABILITY NOT YET DEMONSTRATED`

This document records the v1.5.0 engineering work: the diagnosis of why the
v1.4.0 baseline measured 0% syntax-valid Python, the corrections to the
evaluation, serving and geometry machinery, the instruction-learning
foundation, and a bounded synthetic learning experiment whose result is
reported honestly.

> **Three claims kept apart.** *Engineering qualification*: the machinery is
> correct, tested and bounded. *Capability qualification*: a checkpoint
> demonstrably writes better Python than it did before — **not established**
> (V15-C1 is `INSUFFICIENT_EVIDENCE`). *Corpus readiness*: an authorised
> corpus exists — **not established** (D1–D5/D3 unresolved, zero approved
> sources).

## 1. Architecture changes

Nothing about the model or the tokenizer changed. The changes are boundaries
around them:

```text
  evaluation/python_eval/surfaces.py    tracks A/B/C, program assembly, contract gate
  evaluation/python_eval/metrics.py     per-surface rates, empty/truncated, mismatches
  evaluation/python_eval/author_cases_v15.py  the v1.5.0 surface-aligned suite
  training/geometry.py                  checkpoint/tokenizer/geometry inspector (fail closed)
  training/instruction.py               instruction contract + supervised sequence builder
  training/fixtures/instruction_synthetic_v1.jsonl  authored fixtures (not a dataset)
  data/python_v1/readiness.py           read-only corpus readiness report
  scripts/build_synthetic_diagnostic_corpus.py  family-separated diagnostic corpus
  serving/openai_server.py              unknown model id refused; base surface raw text
  serving/local_inference.py            EOS terminator corrected
  evaluation/python_eval/sandbox.py     local isolation detection
```

The language-neutral core is untouched: `training/model.py`, the causal
objective, the sequence builder, the checkpoint schema and the prompt
contract are unchanged. Python specificity lives in the dataset, the
evaluation contracts, the syntax analyser and the instruction contract.

## 3. Completion and instruction evaluation contracts

`evaluation/python_eval/surfaces.py` defines three surfaces:

| Surface | Input | Judged on | Requires |
| --- | --- | --- | --- |
| `base_completion` | a code prefix | prefix + continuation parsed as one program | a completion-capable checkpoint |
| `instruction_to_code` | a natural-language instruction | the extracted program | an instruction-qualified checkpoint |
| `chat_instruction` | an instruction through the chat contract | the extracted program | a chat-qualified checkpoint **and** a matching contract id |

A case whose surface the checkpoint is not qualified for is **refused**
(`contract_mismatch`), never converted. The v1.4.0 twenty-case suite is
unchanged and remains the baseline; the v1.5.0 suite is a separate file with
16 surface-tagged cases.

New metrics: per-surface rates, complete-program rate, empty-output rate,
truncation rate, contract-mismatch count — each with its denominator, and
`null` where a measurement is unavailable.

## 4. Tokenizer and geometry assessment

`training/geometry.py` inspects a checkpoint, a tokenizer and a model
configuration and reports every incompatibility. It reads metadata and weight
shapes; it never loads a checkpoint into a model and never resizes anything.

| Artifact | Vocabulary | Embedding rows | Verdict |
| --- | --- | --- | --- |
| M7 checkpoint + `qm_code_bpe_v0.json` + `code_m3_9m.yaml` | 5,822 | 5,822 | compatible (step 300, 75 tensors) |
| S3 checkpoint (`runs/code_pretrain`) + the same tokenizer | 32,768 (checkpoint) | 32,768 | **incompatible**: 26,946 embedding rows the 5,822-id tokenizer can never address |

The S3 investigation is therefore conclusive without any guesswork: the
orphan checkpoint exists, its geometry is 32,768-wide, **no tokenizer in this
repository has that vocabulary**, and it cannot be served with the frozen
tokenizer. Its sampled output is degenerate. A tokenizer for it would have to
be trained and approved first; reconstructing one from guesses is forbidden
and was not attempted.

**D6 recommendation (evidence-based, not decided here).** Keep the S2 rung
(5,822 ids) for the next training stage, because the corpus that would
justify a 32,768-wide vocabulary does not exist yet; measure the tokenizer's
Python cost (2.85–2.97 characters per token, 32–43% identifier fragmentation)
as a known limitation rather than as a reason to migrate before the data
exists. Re-run the compatibility inspector against the S3 checkpoint when a
32,768-id tokenizer artifact exists and is approved.

## 5. Training objective verification

The objective was reviewed and re-tested rather than rewritten: exactly one
label shift, padding targets masked with `IGNORE_INDEX`, token-mean
normalisation over the accumulation window, suffix-only padding (safe under
causal masking), explicit document terminators, and a checkpoint that carries
the scheduler, RNG, sampler and consumed-token state. The v1.3.0
qualification suite (including deterministic resume) still passes unchanged.

## 6. Instruction-learning foundation

`training/instruction.py` defines `quantsmind.instruction_example/1`: an
example carries an id, language, instruction, optional context, response,
provenance, authorization state, contamination class, prompt contract, token
budget and split.

* **Production mode** refuses an example without provenance or a licence, an
  example that is not `approved`, and an example marked `seen_in_training`.
* `build_supervised_sequence` renders the prompt through the declared chat
  contract, masks the prompt half out of the loss, supervises the response
  and the terminator, and reports the supervised positions, the truncation
  flag and the contract used.
* An unsupported prompt contract is refused.
* The four authored fixtures are marked `authorization: pending`, so they
  **cannot** pass production validation; they exist to test token placement,
  masks, truncation and determinism.
* No checkpoint is labelled instruction-qualified by this module. That label
  may only be set by a separately authorised training and evaluation process.

## 7. Synthetic experiment (bounded)

Corpus: `scripts/build_synthetic_diagnostic_corpus.py` — 24 modules over six
template families; four families train, two are **held out** entirely, so
validation measures transfer rather than memorisation. It is a diagnostic
fixture, not a corpus.

Run: S2 rung, CPU, 30 optimizer steps, 9,882 tokens, fixed seed, no external
data, no model scaling.

| Measurement | Value |
| --- | --- |
| Initial training loss | 8.623 (uniform baseline `ln(5822)` = 8.669) |
| Final training loss | 2.661 |
| Validation loss (synthetic val split) | 2.912 |
| Next-token accuracy (validation split) | **30.3%** (100/330) |
| Held-out family completion syntax | **0/16** (untrained baseline: 0/16) |

The pipeline learns the synthetic distribution — a 30.3% next-token accuracy
against a 1-in-5,822 chance baseline — and **does not transfer** to unseen
template families: the model emits newlines instead of a function body. This
is memorisation of the training families, not learning to write code.

## 8. Serving fixes

* **Unknown model id refused.** `/v1/chat/completions` now returns HTTP 400
  with `code: model_not_found` for any id other than the loaded model. The
  previously echoed id is gone; `/v1/models` is unchanged. The v1.4.0 agent
  route is unaffected because the agent sends the discovered id.
* **Base checkpoints are served raw text.** The server reads the checkpoint's
  recorded training mode; a pretraining checkpoint is a completion model, so
  the chat template is not applied and a multi-turn history is refused with a
  clear message instead of being flattened.
* **EOS correction.** The legacy `generate()` helper now stops on the
  tokenizer's own `<eos>` id.

**Residual:** the IQ-1 evidence was gathered while the server still applied
the chat template to a base checkpoint. The transport contract is unchanged,
but the route should be re-verified by the owner after this change; it was
deliberately not re-run in this milestone.

## 9. Functional execution safety

`detect_local_isolation()` inspects the host read-only: Docker, Podman, WSL,
bubblewrap and firejail. On this host Docker, Podman, bubblewrap and firejail
are **absent**; `wsl.exe` is present but unusable without provisioning a
distro, which is a system change that is neither authorised nor attempted.
Functional correctness therefore stays **BLOCKED**, the executor keeps
refusing to execute generated code, and only syntax-level results are
reported. No sandbox package was installed.

## 10. Corpus authorization readiness

`python -m data.python_v1.readiness --contract data/contracts/python_v1.yaml`
reports, read-only: sources declared (0), approved (0), denied (0), provenance
and licence metadata completeness, the contamination registry state, split
readiness, tokenizer compatibility, and **production training authorised:
False**. It never approves a source and never mutates the registry. The
decision register (D1–D5, D3, D6) is printed with the remaining human
decision for each.

## 11. Agent compatibility preservation

The Taksh-side contract is preserved: discovery, non-streaming chat, error
mapping, token limits, and the explicit refusals for streaming, tool calling
and structured output all still hold, now with unknown model ids refused.
The QuantsMind-Agent repository was not modified by this milestone.

## 13. Outstanding blockers

1. **Corpus and licensing (D1–D5, D3).** Zero approved sources; production
   training stays unauthorised and every capability number is synthetic.
2. **Training exposure.** 30 steps over 9,882 tokens cannot teach code
   structure. The next run needs an authorised corpus and a step budget
   agreed in advance (D7/D14).
3. **Vocabulary (D6).** Identifier fragmentation of 32–43% is a real cost, but
   migrating before the data exists would change the experiment, not the
   outcome.
4. **Functional correctness** remains unmeasurable without an isolation
   mechanism.
5. **Prompt surfaces.** Instruction capability is untested because no
   instruction-qualified checkpoint exists.
6. **IQ-1 re-verification** after the base-surface serving change.

## 14. Proposed v1.5.0 → v1.6.0 transition criteria

1. An approved corpus with a `corpus_ready: true` manifest.
2. A pre-registered training budget (steps, tokens, wall clock) for one
   authorised run, with the same evaluation suite, surfaces and generation
   settings before and after.
3. A comparable coding-improvement measurement on the **base-completion**
   track: the same cases, the same budget, the same validation rules.
4. Instruction capability measured only on an instruction-qualified
   checkpoint, with the track-B/track-C contract gate satisfied.
5. A functional-execution mechanism, or an explicit acceptance of
   syntax-only evaluation.

## 15. Final disposition

**`v1.5.0 ENGINEERING QUALIFIED — CODING CAPABILITY NOT YET DEMONSTRATED`**

The engineering machinery is qualified: the evaluation surfaces are separated,
the geometry inspector fails closed, the objective and masks are verified, the
serving defects are corrected, the instruction contract enforces
authorization, and the corpus gate remains default-deny.

What is **not** claimed: Taksh has not demonstrated useful Python programming
ability. The only learning evidence in this version is a bounded synthetic run
whose loss fell while its completions on unseen template families stayed
invalid (0/16). No comparable pre/post coding measurement exists, so the
capability gate is `INSUFFICIENT_EVIDENCE`, and the flags stand as:
production corpus authorization **not established** (zero approved sources),
functional execution **BLOCKED** (no isolation mechanism), real-agent
compatibility **preserved but pending re-verification** after the
base-surface serving change.
