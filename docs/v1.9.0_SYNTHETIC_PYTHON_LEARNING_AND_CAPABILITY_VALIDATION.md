# Taksh v1.9.0 — Synthetic Python Learning and Capability Validation

**Disposition:** `v1.9.0 ENGINEERING QUALIFIED — PATTERN LEARNING ONLY`

This milestone ran a bounded, synthetic-only learning experiment on the
existing S2 model and measured what actually happened. The result is honest
and narrow: **the model learned the shape of a Python function, not how to
compute with it.** No production corpus, no benchmark, no capability claim,
and no promotion of the experimental checkpoint.

> **Separate flags:** synthetic generalization — **not demonstrated**
> (`SYNTHETIC_PATTERN_LEARNING_ONLY`) · production coding capability —
> `NOT_DEMONSTRATED` · real-data corpus authorization — `BLOCKED` ·
> functional correctness — `BLOCKED` · real-agent integration — `NOT_PERFORMED`.

## 1. Executive summary

| Question | Answer |
| --- | --- |
| Can S2 learn on a controlled synthetic curriculum? | Yes, measurably: training loss 8.663 → 4.536 in 8 steps (763 tokens), validation 6.337 → 5.574. |
| Does that become valid Python? | The trained model emits parseable, function-shaped completions on **every** partition: 8/8 syntax-valid and 8/8 complete-function on A, B and C, against 0/8 for the baseline checkpoint. |
| Is that generalization? | **No.** 100% of the completions are degenerate, 0/8 match the target semantics and the structural similarity to the reference is 0.0. The model reproduced the template; it did not learn the computation. |
| Verdict | `SYNTHETIC_PATTERN_LEARNING_ONLY` |
| What limited it? | 8 optimizer steps over 763 tokens — the experiment budget, not the architecture. The extended diagnostic was not run because the 120-second per-subprocess ceiling on this host bounds a single run. |

## 4. Synthetic curriculum

`training/synthetic_curriculum.py` generates six Python families —
arithmetic, conditionals, list transformations, string transformations,
dictionary operations and loop aggregation — plus a composed family. Nothing
is copied from a benchmark or a corpus; every sample comes from an explicit
grammar with a per-case salt, so samples of one family differ only in their
parameters and names.

| Partition | Size | Purpose |
|---|---:|---|
| train | 120 | four families (`arithmetic`, `conditionals`, `list_ops`, `string_ops`) |
| A — in-distribution holdout | 40 | the trained families, unseen parameter combinations and unseen function names |
| B — compositional holdout | 30 | a new composition of familiar operations (`filter` then `sum`) |
| C — family holdout | 40 | two families never trained on (`dict_ops`, `loop_agg`) |

## 5. Split and contamination controls

`contamination_report` measures exact duplicates, parameter-erased
(normalized) duplicates, shared target solutions, withheld-family leakage and
structural similarity against the training split. Result for the frozen
curriculum (digest `7c50dbf3…`): **CLEAN**, 0 violations, and maximum train
similarity of 0.13 (B) and 0.06 (C) — the structural partitions share almost
nothing with training. Partition A shares templates with training by design
and is reported separately, because A measures the same families with new
parameters.

Two generator defects were found and fixed during this milestone: a
non-deterministic salt counter and a `PYTHONHASHSEED`-dependent seed, both of
which broke reproducibility. The curriculum is now byte-identical across
builds and processes.

## 9. Post-training evaluation and classification

| Metric | Baseline | Trained | Delta |
|---|---|---|---|
| Syntax valid, A | 0/8 | 8/8 | +1.000 |
| Syntax valid, B (compositional) | 0/8 | 8/8 | +1.000 |
| Syntax valid, C (family holdout) | 0/8 | 8/8 | +1.000 |
| Complete function, A/B/C | 0/8 | 8/8 | +1.000 |
| Degenerate, A | 0/8 | 8/8 | +1.000 (worse) |
| Exact target, A/B/C | 0/8 | 0/8 | 0.000 |
| Structural similarity to reference | 0.0 | 0.0 | 0.000 |
| Training loss | 8.663 | 4.536 | −4.127 |
| Validation loss | 6.337 | 5.574 | −0.763 |

**Classification: `SYNTHETIC_PATTERN_LEARNING_ONLY`.** The completion *shape*
improved on every partition, including the two held-out ones, but the outputs
never became semantically correct: every completion is degenerate and none
matches the reference. The classifier requires held-out syntax gain **and** a
falling degenerate rate **and** movement toward the targets before it will
call a run generalization; this run fails the second and third conditions, so
it is reported as pattern learning.

## 10. Held-out generalization findings

The trained model reaches the same 8/8 on A, B and C, which is the signature
of a memorised template rather than of generalization: the same shape is
emitted regardless of the family, including families it never saw, and the
content is degenerate in every case. Nothing here supports a claim of
compositional or family-level transfer.

## 11. Repetition analysis

The baseline checkpoint is not degenerate on A/B but is degenerate on 4/8 of
the family holdout; the trained model is degenerate on 8/8 everywhere. The
v1.8.0 finding (greedy decoding collapses into repetition) is confirmed on
this curriculum as well, and 763 tokens of training did not reduce it — it
replaced "invalid and repetitive" with "parseable and repetitive".

## 12. Checkpoint integrity and reproducibility

The experimental checkpoint is written to an isolated experiment directory,
carries the v1.1.0 `/2` provenance contract with `mode: synthetic`, and loads
independently. Historical checkpoints, the tokenizer and the frozen benchmarks
are byte-identical to their committed state. The curriculum digest, dataset
seed, training configuration and evaluation budgets are recorded in the
experiment report. Repeatability of the *training* run is not claimed: it was
executed once inside the environment's time ceiling.

## 18. Verification appendix (post-experiment audit)

### 18.1 Task-conditioning diagnostic

Twenty-four frozen cases (8 per partition), greedy, 64-token budget, the
surviving experimental checkpoint, the frozen curriculum
(digest `9e6252f2…`). Static analysis only; no generated code was executed.

| Measurement | Result |
|---|---|
| Evaluation prompts | 24 |
| Unique raw completions | **1** (all 24 identical) |
| Unique normalized completions | 1 |
| Unique function bodies | 1 (per partition as well) |
| Most common completion frequency | **24/24** |
| Most common body frequency | 24/24 |
| Distinct AST shapes | 0 (no completion parses) |
| Prompt-name agreement | 0/24 |
| Parameter-name agreement | 0/24 |
| Parameter-count agreement | 0/24 |
| Requested-operation agreement | 0/24 |
| Syntax-valid completions | 0/24 |
| Exact-target completions | 0/24 |
| Truncated / EOS | 24/24 truncated, 0/24 EOS |
| Degenerate completions | 24/24 |

The emitted completion is a run of 64 quote characters for **every** prompt,
across all three partitions and all six families. The model does not vary its
output with the task at all: not the function name, not the parameters, not
the operation.

**Diagnostic classification: `GENERIC_TEMPLATE_COLLAPSE`.** This is stronger
evidence than the earlier "8/8 syntax-valid" figure, and it points the same
way: the model learned a single emission pattern, not a family of functions.

### 18.2 Training token accounting

| Measurement | Verified value |
|---|---|
| Unique training examples (corpus train shard) | 60 |
| Unique tokenized tokens in the corpus | 2,899 |
| Windows built (context 256) | 60 |
| Input token positions in the corpus | 2,839 |
| Loss-bearing target tokens in the corpus | 2,839 |
| Forward passes | 16 (8 optimizer steps × 2 accumulation microsteps) |
| Backward passes | 16 |
| Gradient-accumulation microsteps | 16 |
| Optimizer updates | **8** (confirmed in the checkpoint's `step`) |
| Windows drawn / reused | 16 drawn, 16 unique, **0 reused**, epoch not restarted |
| Reported 763-token interpretation | supervised (loss-bearing) target tokens processed over the 16 drawn windows — **not** unique corpus tokens and **not** input positions |
| Accounting verdict | **PASS** |

The 763 figure is 27% of the 2,839 available loss-bearing tokens: the run
consumed 16 of the 60 windows, without repetition. The training loop was
verified in `training/train.py`: gradients are zeroed per optimizer step, each
microbatch's mean loss is scaled by its share of the window's supervised
tokens, gradients are clipped before the step, the learning rate is taken from
the warmup/cosine schedule at the step index, and the run stops on the step,
token or wall-clock limit. Eight optimizer updates did occur.

### 18.3 Reproducibility limitations

Deterministic curriculum and stable hashes are confirmed; the frozen
partitions, seeds, configuration and evaluation budgets are recorded; the
experimental checkpoint loads independently. **Independent training-run
reproducibility remains unproven**: one run was executed inside the
environment's time ceiling, and the artifact directory was reused by a later
diagnostic probe, which is exactly the kind of overwrite that makes a
single-run claim fragile. V19-G17 stays **PARTIAL**.

### 18.4 Updated scientific interpretation

`SYNTHETIC PATTERN LEARNING ONLY` is retained, with a sharper statement: the
trained checkpoint emits the same degenerate output for every prompt and every
family, so the run demonstrates neither task-conditioned behaviour nor
transfer. The corrected headline is that the surviving artifact shows a
**generic template collapse** (1 unique completion across 24 prompts), which
is *more* consistent with the original report's interpretation than the
superseded 8/8 syntax-valid figure was. No functional correctness, no
generalization, and no production coding capability is claimed.

## 17. Recommended v1.9.0 → v2.0.0 direction

1. Re-run the same experiment with a real budget (hundreds of steps over
   millions of tokens) under a compute allowance that does not fit a
   120-second subprocess, and keep the same frozen evaluation protocol.
2. Add a repetition-aware training objective or a repetition penalty in the
   sampling path *only* if a controlled comparison shows it helps, since the
   trained model traded invalid output for degenerate output.
3. Keep the curriculum generator as the regression harness for the training
   stack: it is deterministic, uncontaminated and cheap.
4. Only then reconsider the corpus decision (D1–D5) and the geometry
   decision (D6) with a measured baseline in hand.
