# Taksh — Positioning Statement

**Date:** 2026-11-14
**Category:** Coding-only AI / sovereign software engineering intelligence
**Status:** product direction and release target; not a capability claim

---

## One line

> **Taksh is the sovereign coding genius: an independently developed, locally deployable coding AI whose capability is proven by frozen evidence, not marketing.**

---

## What Taksh is

Taksh is for teams that need AI to write, repair, test, review and explain code without handing source code to an opaque external service.

It is:

- coding-first, not general-purpose;
- sovereign by design: own tokenizer, data lineage, weights and release controls;
- locally deployable with explicit security boundaries;
- deterministic to evaluate;
- built for private repositories and regulated environments;
- auditable from prompt to checkpoint to benchmark;
- designed for enterprise integration into IDE, CI/CD and engineering workflows.

## What Taksh is not

Taksh is not:

- a general chatbot;
- a finance or multimodal product;
- a wrapper around another company's model;
- a hosted service that trains on user code by default;
- a replacement for human code review;
- a released product with proven superiority before benchmarks pass;
- a magic model that can be claimed capable because its architecture exists.

---

## Target customer

Primary buyer: organizations that cannot or will not upload sensitive repositories to an external AI API and need measurable coding assistance.

Examples:

- regulated enterprises with data-residency requirements;
- banks, public-sector organizations and defense-adjacent software teams;
- software vendors shipping private/customer-specific coding intelligence;
- internal platform teams that require auditability and provenance;
- global engineering teams that need a local model and a controlled release process.

---

## The customer promise

Taksh should eventually sell this promise:

> "Bring your repository and your rules. Taksh helps you generate, repair, test and review code on your infrastructure, with an auditable trail and measurable release gates."

It should not promise: "Taksh writes perfect code" or "Taksh is the world's best coder" before product evidence exists.

---

## Differentiation

| Differentiator | Why it matters |
|---|---|
| Own weights and tokenizer | no opaque dependency; release artifacts can be inspected and hashed |
| Local-first inference | source code stays under customer control |
| Evidence-gated releases | claims are reproducible and auditable |
| Regulated-enterprise fit | residency, audit, kill switch and approval workflows |
| Coding-only focus | no dilution across finance, chat or multimodal |
| Software-architecture assistance | supports design decisions without replacing implementation |
| Multilingual coding ambition | valuable for polyglot enterprise estates |

---

## Competitive wedge

Incumbents win semantic breadth, capital and distribution. Taksh's wedge is **sovereign coding depth with evidence**.

The sequence is:

1. prove one strong Python model;
2. prove repair and tests;
3. prove repository-aware engineering;
4. prove 16 languages, then the 53-language catalogue;
5. prove agentic coding under permission boundaries;
6. only then claim "best", with evidence.

---

## Release language

Use this language publicly:

- "Taksh is a sovereign coding AI research and engineering program."
- "Taksh's current development builds infrastructure, not capability claims."
- "Capability will be published only after frozen benchmarks pass."
- "Taksh is designed for private-code environments where auditability matters."

Do not use this language yet:

- "Taksh outperforms …" (no comparative evidence);
- "Taksh is ready for production" (no product release);
- "Taksh is a world-class coder" (not measured);
- "Taksh can autonomously build software" (not qualified).
