## 4. Authorization framework (Workstream A)

`data/python_v1/authorization.py` implements `quantsmind.source_manifest/2`
with six explicit states: `pending_review`, `approved`, `rejected`,
`revoked`, `expired`, `insufficient_evidence`. Only `approved` is eligible.

A manifest records: source id, name, origin, publisher, revision, source
type, declared licence, licence-evidence reference, intended use, commercial
use, modification/redistribution assessment, attribution obligations,
provenance evidence, collection method, personal-data risk, secrets risk,
third-party-rights risk, contamination assessment, authorization state,
reviewer, decision timestamp, rationale, revocation status and evidence hash.
Unknown facts are written as `unknown` or `not_assessed`; no legal conclusion
is fabricated.

Fail-closed refusals (stable reason codes): `malformed_source_manifest`,
`authorization_state_is_<state>`, `missing_reviewer_authorization`,
`missing_decision_timestamp`, `authorization_revoked`, `authorization_expired`,
`missing_license_evidence`, `license_not_assessed`, `license_not_permitted`,
`revision_mismatch`, `use_out_of_approved_scope`,
`provenance_not_established`, `unmitigated_<risk>`.

**A request is not an approval.** `build_review_packet` produces the packet a
reviewer needs — identity, evidence collected, missing evidence, known risks,
proposed use, the human decisions required and the explicit blockers — and
always states that it implies no approval. A permissive licence name alone
never grants eligibility.

**Approved-source count: 0.** The shipped contract still declares zero
sources, the readiness command reports `production authorized: False`, and the
default decision is `deny`.

## 5. Corpus preparation (Workstream B)

`data/python_v1/authorized_ingest.py` defines the ingestion contract:
approved source manifest, immutable revision, local path, expected hashes,
processing configuration, output directory and pipeline version.

Order of operations: authorize every source → verify each source's revision
against the approved value → only then read files. A refusal aborts the build
with `source_not_authorized` or `revision_mismatch`.

The build reuses the v1.2.0 pipeline and adds a build manifest
(`quantsmind.authorized_corpus_build/1`) with source revisions, authorization
references, pipeline version, configuration digest, input and output hashes,
accepted/rejected counts and reasons, deduplication counts, contamination
verdict, split counts and environment metadata. Two builds of the same
approved material produce identical hashes (tested).

Quality controls now also exclude **embedded instructions** (text that tries
to steer a model, e.g. "ignore all previous instructions"), because such a
file teaches the model to obey content found in files rather than in the
prompt.

Contamination screening protects both the v1.4.0 twenty-case suite and the
v1.5.0 sixteen-case suite; a corpus record equal to a registered case is
removed (tested). Synthetic fixtures are marked `synthetic_test_only` and can
never be approved for production.

Observations that matter more than the table: the ~30M row is the orphan
`code_30m.yaml` geometry, whose 32,768-wide vocabulary matches **no**
tokenizer in this repository, so it is not a candidate until D6 is decided;
the embedding share of the 1B row is ~6.7%, so vocabulary choice dominates
the small models; and **no parameter count guarantees coding capability**.

Pathways (none provisioned): (1) strictly local CPU-only research on the S2
rung — the correct next step while no corpus exists; (2) limited-budget
accelerated training, only after a corpus is approved and a budget is agreed;
(3) larger-scale research with dedicated compute — premature, and it would
change the experiment before the data exists.

**Architecture decision.** Continue with S2 for diagnostics; do **not** design
or migrate a larger rung in this milestone; defer scaling until a legally
approved corpus exists, because capacity cannot be measured without data.
D6 remains an explicit open decision.

## 13. Risks and limitations

* No authorised corpus, so every capability number remains synthetic or
  historical; **V16-D1 is BLOCKED** and production training stays forbidden.
* No isolated execution, so functional correctness is unmeasured.
* The completion track is budget-limited: 8/8 completions truncated at 64
  tokens in every run, so syntax validity is measured on partial programs.
* The 8-case completion track is a smoke suite, not a benchmark.
* The v1.5.0 IQ-1 staleness (prompt rendering) is unverified against the
  real agent.
* The synthetic training diagnostic overfits its families and transfers
  poorly (0/16 held-out-family completions).
