# Taksh v1.1.0 - Training Integrity and Reproducibility

Status: implemented and locally verified on CPU. Version disposition: QUALIFIED
for the repository-scope gates below; the full retraining reproduction drill was
not run (see Limitations).

## Scope

This release makes the train/serve prompt path canonical, versions the tokenizer
control-token contract, records checkpoint provenance, refuses incompatible
loads, and makes short CPU runs deterministic.

## Contracts

- Prompt contract: `qm.chat_instruction/2` (legacy: `qm.plain_instruction/1`).
  Control markers are `<|system|>`, `<|user|>`, `<|assistant|>`, `<|end_of_turn|>`,
  `<|bos|>`, `<|eos|>`. In v2 each marker is one tokenizer id, so no marker can
  appear as plain text inside user content.
- Checkpoint schema: `quantsmind.checkpoint/2` adds a `provenance` block with 11
  fields: schema, contract_id, tokenizer file hash, tokenizer fingerprint,
  tokenizer vocab size, model config, model config hash, git revision, library
  versions, seed, and creation timestamp. Schema `/1` remains loadable.

## Implementation

- `training/tokenizer_contract.py`: canonical contract constants, detection,
  validation, tokenizer construction, fingerprinting.
- `training/chat_template.py`: v2 renderer; v1 behavior unchanged and explicit.
- `training/checkpoint_schema.py`: provenance build/validate/verify helpers.
- `training/pretrain.py`: writes `/2` when provenance is supplied; validates any
  `/2` block on load and keeps `/1` compatibility.
- `training/determinism.py`: torch/numpy/random seeding with deterministic
  algorithms enabled in warn-only mode.
- `training/sft.py`: contract-aware pair encoding and provenance capture.
- `serving/openai_server.py`: renders via the stored tokenizer contract, reports
  `prompt_contract` in `/health`, verifies provenance for `/2` checkpoints.
- `serving/local_inference.py`: strict weight loading with shape/key report.
- `serving/server_security.py`: `verify_serving_contract` gate before serving.
- `serving/code_chat.py`: prompt rendering through `render_for`.

## Release gates

| Gate | Evidence |
| --- | --- |
| 1. One renderer for training and serving | `test_gate1_train_and_serve_render_identically` |
| 2. Single-id control tokens, no textual delimiters | `test_gate2_*` (three tests) |
| 3. No delimiter leakage; legacy refuses multi-turn | `test_gate3_*`, server regression suite |
| 4. Causal mask, shifted labels, prompt mask, padding | `test_gate4_*` (three tests) |
| 5. `/2` roundtrip plus mismatch refusal; `/1` loads | `test_gate5_*` (two tests) |
| 6. Controlled tiny learning run | `test_gate6_tiny_sample_learning_is_controlled` |
| 7. Save/reload/resume bit-exact | `test_gate7_save_reload_and_resume` |

The tiny learning run used a 32-wide, 1-layer model, 60 AdamW steps on a fixed
synthetic batch, and required the final loss to fall at least 1.0 nat below
`ln(5828) = 8.67`.

## Compatibility and migration

- Legacy `/1` checkpoints load with a warning and serve under
  `qm.plain_instruction/1`; they cannot use multi-turn chat.
- `/2` checkpoints are refused when contract id, tokenizer identity, model config
  hash, or schema do not match the serving environment.
- The tokenizer file is unchanged: `tokenizer/qm_code_bpe_v0.json` (vocab 5822)
  gains six appended control ids, giving a 5828-token embedding table. The S2
  parameter count remains 9,359,104.
- `serving/code_chat.py` keeps `format_prompt` backward compatible and uses the
  tokenizer contract when one is supplied.

## Limitations

- No full S2 retraining was performed; the learning evidence is the bounded
  tiny-model gate only.
- The two-environment reproduction drill from the roadmap was not executed;
  it needs a second clean environment and an owner-approved compute budget (D14).
- No GPU throughput or VRAM measurements were taken.
- On this host the default pytest temp root is not writable, so runs used
  `--basetemp` under the approved temp directory. This is environmental, not a
  product requirement.
- Changes are uncommitted pending review.
